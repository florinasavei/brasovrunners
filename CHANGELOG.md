# Changelog

Every change to the documentation baseline, newest first. The heading of the top entry is
the current baseline and must equal the `PROJECT_BASELINE` marker on line 1 of every root
document; `docs:check` enforces that. Application releases will be added here under their
own tags once code exists (`README.md` § Versioning).

Format: one entry per baseline, three parts: what changed, which documents, why (pointing at
the `DECISIONS.md` section). Keep entries short; the detail lives in `DECISIONS.md`.

## BR-V1.16-2026-09-04

- **The registration lifecycle, end to end, against a real database and under real concurrency.** Submission, email confirmation, the 30-minute declaration hold, capacity, the waiting list, self-unregistration and the registration-maintenance job (BR-REQ-030-01, 031-01, 033-01, 034-01, 034-02, 034-03, 035-01, 035-02, 036-01, 036-02). `modules/registrations/service.ts` is the allocator every path — a first submission, a restart of a cancelled registration, the scheduled job — goes through, and `tests/concurrency/capacity.test.ts` proves twenty simultaneous confirmations against one free place produce exactly one winner and that a released place goes to the front of the waiting list, never to a concurrent new registration, against real PostgreSQL rather than the single-connection PGlite the rest of the suite runs on.
- **The pilot's capacity guard is gone.** `events_capacity_must_be_null_during_pilot` is dropped, last, after the concurrency suite above passed — the order WEEKEND.md and `CLAUDE.md` both named as the only safe one. An event may now carry a real capacity; absent capacity still means unlimited.
- **Staff sign-in is Auth.js with the Zitadel provider — again.** `DECISIONS.md` §24 (BR-V1.15) decided "Auth.js alone, no external identity provider" over a plan named in earlier baselines; nothing was ever built against that decision beyond the development switcher, and no `staff_users` row ever held a subject under it. §26 reverses it: Auth.js with Zitadel, `staff_users` unchanged as the server-side allowlist, an unknown Zitadel account refused before a session issues. `STAFF_AUTH_MODE` gains `provider`; the column is `zitadel_subject` again, via a real migration. `AGENTS.md` §13.1, §12.1, the provider tables in §3.1/§7.1/§7.2, `SETUP.md` §15, `README.md`'s authentication model, `CLAUDE.md` and `WEEKEND.md` are corrected to match. `DECISIONS.md` §26.
- **Legal documents are versioned, immutable, and never invented outside a developer's machine.** `legal_documents`/`legal_document_translations` (AGENTS.md §12.5), the two public routes, and a `PLACEHOLDER` version seeded only in local and test — refused, loudly, anywhere else. Registration itself refuses when nothing is approved (BR-REQ-053-01), which is what actually protects qa and production; the seed guard is the second, independent promise that invented text specifically never reaches them. `DECISIONS.md` §27.
- **Ten transactional message types, in Romanian and English, sent through the outbox that already existed.** `modules/notifications/templates.ts` and `render.ts` fill the `EmailRenderer` seam `processOutboxBatch` was built to receive. A message that carries an action link mints its token at send time, not at enqueue time — the outbox row itself never holds a secret, matching §14.5, because a message queued now and rendered minutes later needs a token that still exists when it is actually needed.
- **The email outbox and registration-maintenance jobs, and the Mailgun delivery webhook.** `POST /api/internal/jobs/email-outbox` and `.../registration-maintenance`, both behind a constant-time-compared `JOB_SECRET`; `POST /api/webhooks/mailgun`, verifying Mailgun's own HMAC signature and rejecting a stale one. No in-process interval: this application deploys to Vercel serverless functions, which have no persistent process for one to live in, so the external scheduler is the only mechanism, not a fallback.
- **A backoffice screen for registrations, Administrator only.** List, filter by event and status, one registration's full timeline, a state-aware resend that can only ever send what AGENTS.md §15.8 allows for the current status, and a CSV export with formula-neutralized cells (§15.10). No email address appears anywhere this role boundary does not already guard.
- **`/api/health`.** Database reachability plus each scheduled job's own liveness, degraded rather than down when a job is stale or has never run — a stalled scheduler delays a notification, per §16.2 it does not put the site in a broken state.
- **`engines.node` states the major, not the patch, so a host can actually install it.** The first real Vercel build refused: `engines.node` demanded `22.14.0` exactly and the build image ships 22.23.2, which a host cannot change because it selects a Node *major*. `.nvmrc` still pins the exact patch for developers and CI, which is what reproducibility actually needs; `engines.node` is now `22.x`. `SETUP.md` §26 also records that each Vercel project needs `ENABLE_EXPERIMENTAL_COREPACK=1`, without which the build runs the image's bundled Yarn 1 against a Yarn 4 lockfile.
- **544 unit and integration tests — up from 420 — and five concurrency tests against real PostgreSQL, up from three.** New: the registration state machine and capacity formula exhaustively as pure functions, the full lifecycle and restart paths against PGlite, the maintenance job's promotion and event-started closure, all ten message templates in both locales, the Mailgun signature and job-secret checks, and the admin resend's role boundary and refusal for a status with nothing to send. The existing 44 end-to-end runs stay green, including the new footer added to every page's shared chrome, but were not extended with new specs for the participant-facing registration pages themselves — those are proved by the integration suite and a manual walkthrough against real PostgreSQL, not yet by Playwright.

## BR-V1.15-2026-09-04

- **Staff identity decided, and the contradiction removed.** `AGENTS.md` §13.1 said Auth.js with the Zitadel provider and §12.1 named the column `zitadel_subject`, while `CLAUDE.md` and `WEEKEND.md` recorded the direction as Auth.js alone. Decided: **Auth.js alone, `staff_users` as the server-side allowlist, no external identity provider**, and the column is `auth_subject`. §13.1, §12.1, the provider tables in §3.1, §7.1 and §7.2, `SETUP.md` §15 and every environment list are corrected. The Auth.js Zitadel provider was verified as real before it was dropped: this is a decision about what a five-person club should operate, not a discovery. `DECISIONS.md` §24.
- **The mini CMS, event half, built during M1 rather than M5 — deliberately, on the record.** Until now, changing an event meant editing `src/db/seeds/pilot.ts` and re-running the seed: a developer and a deploy for a sentence about a start time. BR-REQ-050-01, BR-REQ-051-01 and BR-REQ-051-02 keep their `Release: M5` field and gained a **Status** line naming what exists; the plan moved, the requirements did not. `DECISIONS.md` §25.
- **The organizer story, end to end:** sign in, edit the race, mark it featured, preview it, publish it — per language, without a developer. Backoffice at `/ro/admin`, editor per event, staff-only preview at `/ro/previzualizare/evenimente/[id]`.
- **Three staff roles, asserted on the server.** AUTHOR, EDITOR, ADMIN as a database enum, `getCurrentStaffUser`, `requireStaff` and `requireStaffRole`, and the permission rules as pure functions every action re-checks. Hiding a button is not authorization: the tests call the services directly with the wrong role and expect a refusal, and an Author who reaches `/admin/staff` gets a 404 rather than a hint (BR-REQ-060-01).
- **An Administrator maintains the staff list:** add a colleague by email address and role, change a role, revoke access. No invitation email — there is no sending domain — so the row *is* the invitation and access begins at that person's first sign-in with that address. An Administrator cannot change their own role, remove their own access, or leave the club with no Administrator: three refusals so a club cannot lock itself out. Revoking someone keeps everything they wrote; the attribution columns are `ON DELETE SET NULL`.
- **No staff sign-in method yet, and the backoffice says so.** The method that suits volunteers with no passwords is an emailed link, which needs the club's sending domain — the same blocker registration waits on. `STAFF_AUTH_MODE` is `dev-switcher` in local and test, `disabled` everywhere else, where every staff request is answered by nobody. So the backoffice works on a developer's machine and is unreachable on production until the domain exists. The development switcher of `AGENTS.md` §13.1 is guarded twice: the process refuses to start with it outside local and test, and every function refuses again when called.
- **The editorial workflow, per locale:** DRAFT → IN_REVIEW → PUBLISHED → ARCHIVED. An Author edits their own drafts and submits for review; an Editor or Administrator publishes, unpublishes and archives. An Author editing published content is refused at the server. A save that changes live content is refused unless the warning was answered — a warning nothing checks is a decoration. Romanian can go live while English is still a draft, and BR-REQ-040-02 still makes the other locale a 404 rather than a fallback.
- **Optimistic concurrency, proven with two real connections.** A save carries the version it was loaded with; the guard is one `UPDATE ... WHERE id = ? AND version = ?` with the increment in the same statement, so the second organizer's save re-evaluates against the committed row, writes nothing and comes back as CONFLICT. PGlite is single-connection and cannot express that race, so `tests/concurrency/` runs against a real PostgreSQL via `yarn test:concurrency` — its own Vitest config, out of `yarn check`, and it fails loudly rather than skipping when `DATABASE_URL` is unset.
- **Two times per event.** New `events.race_starts_at`: a race gathers at one time and starts at another, and runners need both. `starts_at` keeps its meaning exactly — when the event begins — because the ordering, the upcoming/past cut-off, the sitemap and the listing all read it. A check constraint keeps the gun time inside the event. The page shows one time or two, each labelled, in the event's timezone; the JSON-LD maps `startDate` to the race start and `doorTime` to the event start (BR-REQ-052-02). Times entered in the backoffice are converted in the event's own zone in two passes, which is what makes the last Sunday in March correct.
- **A map link on the location.** New `events.map_url`, rendered with `rel="noopener noreferrer"`. Stored rather than assembled: `AGENTS.md` §8 forbids a hostname literal under `src/` and exempts no provider, so no maps URL can be built from the coordinates or allowlisted — `yarn docs:check` fails on one either way. https is required at the form and again by a check constraint, so `javascript:` and `data:` cannot be stored by a seed or a hand-written `UPDATE`. Latitude and longitude are unchanged and are not a substitute.
- **A featured event, and the database allows only one.** New `events.featured` with a partial unique index — the same reasoning as the capacity guard, because application code that remembers to clear the previous flag is a race between two organizers. The landing page leads with it in full: dates, distance, meeting point, map link and cost, above the ordinary listing, which no longer repeats it. Ordering is featured → race → soonest.
- **A protected preview** of any draft translation, in the locale of its own URL. Refused before a single row is read, so an anonymous request does not learn whether the draft exists; `noindex` in the page metadata, `X-Robots-Tag: noindex` and `private, no-store` from the proxy for every `/admin`, preview and sign-in path, absent from the sitemap, disallowed in `robots.txt` (BR-REQ-051-02).
- **Slugs are editable before first publication and stable afterwards**, keyed on a `published_at` that is set once and never cleared — unpublishing must not hand back an editable address for a URL people have already followed.
- **The CMS boundary is an allowlist, and it is tested as one.** The editable set is exactly the editorial fields that exist; a form that also posts `editorialStatus`, `version`, `capacity`, an `id` or a rich-text body is rejected rather than quietly applied. No rich text in this batch: §11.3 makes the canonical body validated Tiptap JSON, and a body editor without that contract is the arbitrary-HTML problem the rule exists to prevent. Legal documents have no editor screen in any form; the backoffice states that instead.
- **The seeded anniversary cross is now the featured event, and its excerpt says EXEMPLU / SAMPLE in both languages.** Its date, distance and meeting point are invented, and it is now the first thing a visitor reads. No map link is seeded, which is the hostname rule working rather than an omission.
- New `staff_users` table (`auth_subject` nullable and unique, `email` unique and lowercased by a check, `invited_at`, `first_signed_in_at`), attribution columns on `events` and `event_translations`, and the `locale` enum moved to `src/db/schema/locale.ts` — `events` needs `staff_users` and `staff_users` needed the enum, and Drizzle loads schema modules eagerly, so the cycle was `Cannot access 'locale' before initialization` at migration time rather than a style problem.
- **A language switcher in the header, Romanian first.** Flag, language code and `aria-current` on the one you are reading. It resolves through `/api/locale` on the server rather than swapping the URL prefix, because on an event page the two locales have different slugs — `tura-pe-tampa` and `tampa-trail` are one event — and only the database holds the pair; a prefix swap is a 404, which is the failure BR-REQ-040-01 criterion 5 exists to prevent. A page with no published translation in the other language lands on that language's listing instead. Works with JavaScript disabled, and the header wraps rather than overflowing at 320px.
- **Country flags from `flag-icons` (MIT), copied into `public/flags/` by `yarn flags:sync`** on install and on build, and git-ignored. Only the SVG files are used, never the package's stylesheet, which references all 271 flags in one file. Hand-drawn flags were tried first and were wrong: Romania is 2:3 and the United Kingdom 1:2, so faithful files render at different widths — the set normalises every flag to 4:3, which is the reason to use one.
- **The map link points at the exact meeting point, not at a place name.** `events.latitude` and `events.longitude` — columns the model always had and nothing used — are now editable in the backoffice and are what the link is built from: a park is forty hectares and the start is one corner of it, so a name search puts a runner in the right park and the wrong end. The database refuses half a pair, a value out of range, and a transposed one (Brașov typed backwards is a field in Somalia). `map_url` remains as the override for what coordinates cannot express — a venue page, a drawn route — and still must be https.
- **The map service is configuration, `MAP_LINK_BASE_URL`.** The application appends `?q=<lat>,<lng>`, which Google Maps and OpenStreetMap both understand, so the club can switch provider without a code change — and, more to the point, no map hostname appears under `src/`, which `AGENTS.md` §8 forbids and `yarn docs:check` enforces. Unset, the meeting point is text with no link: a missing map is a missing convenience, a guessed one sends people somewhere else.
- **`SportsEvent` now carries `geo` and `hasMap`** when the club has stated coordinates, so a search result can show the right pin, and the link in the structured data is the same one the page renders.
- **The event address is the map link** on the detail page, and the meeting point carries an explicit "open the map" on the full page. Not in the listing cards: the whole card is already a link, and an anchor inside an anchor is invalid HTML that the browser silently splits. Every map link is a 44px tap target with `rel="noopener noreferrer"`.
- **The owner's standing instruction is written into the rules** rather than left in a conversation: fast, small, and easy for the next person to work on, ranked in `AGENTS.md` §1.5 above everything but correctness. Prefer nothing to a dependency, the platform to a library, and what is installed to something new; a library added for one screen is argued for in the pull request. It is why the flag set arrived with a country field in view rather than for two flags.
- **420 unit and integration tests, 44 end-to-end runs across the 320px and desktop projects, and a three-test concurrency suite.** New: the role and workflow rules exhaustively, the two-time conversion across both daylight-saving boundaries, the new constraints at the database, the CMS allowlist, the preview, staff administration, which paths are private, and an organizer taking an event off the public site and putting it back in a browser.

Previously it showed everything soonest-first, so between seasons the first card was last month's run, which reads as an abandoned site rather than a quiet month. Past events stay published, linkable and in the sitemap.

BR-REQ-040-02 is unchanged — an unpublished locale is a 404 and never a fallback to the other language — and `tests/integration/events/publication.test.ts` still proves it with its own data; the seeded rows simply are published now. The end-to-end suite gained a check that the English page serves English words and that each locale resolves only at its own slug, since the slugs genuinely differ.

- The header lockup is sized with `clamp` rather than fixed pixels. At 28px the mark and wordmark came to 307px side by side, against the 288px a 320px phone leaves after container padding, so the whole page scrolled sideways — a BR-REQ-041-01 criterion 1 failure that only appears below roughly 360px. Fluid rather than a breakpoint, because the overflow is continuous: a breakpoint at 360 would leave 361 broken.

It is confined to that one string because the font contains 129 characters and none of them are Romanian: not ș or ț in either encoding, not ă, â or î. The club's name, spelled properly, remains in the message catalogue and is what the header link announces to a screen reader. The fallback is Roboto 900 italic, which is not a guess — the designer's read-me names Roboto Black Italic as the face Facón was drawn from. The TTF is served unmodified, because the licence forbids altering the file and a 36kB TTF needs no conversion.
- `.gitattributes`: images, fonts and PDFs are declared binary, so no line-ending conversion can corrupt one and no review is buried under a megabyte of diff. Text diffs stay on for everything else, deliberately.

- The club's real logo, wired in. `src/theme/brand.ts` is now the only file in `src/` that may name a colour, a font or a logo path, and the MUI theme is assembled from it. The supplied SVG puts its artwork in a band inside a 3000×3000 canvas, so 61% of the height is empty space every layout would reserve; `public/brand/` holds four cropped, editor-metadata-stripped variants — the full lockup and the mountains alone, each in the club's blue and in white for dark grounds. The masters and the kit photograph are kept unprocessed in `docs/brand/`, out of `public/` because that directory is served to the internet. The two enormous PNG exports are deliberately not committed: 111MB, and git does not forget a blob.
- The site header pairs the mountains with the wordmark set as live text rather than showing the full lockup, which is 2.4:1 — at a height that fits a header, the wordmark inside it renders about four pixels tall. Links home, 44px tap target (BR-REQ-041-01 criterion 6). The mark is duplicated as `src/app/icon.svg` for the browser tab, with a test that the two cannot drift apart — nothing imports a Next file-convention icon, so no compiler would notice.
- Two font *roles* rather than one family — display for headings, body for text. Both resolve to Roboto: the kit's display face takes neither, because it cannot spell a Romanian word.
- Every palette pair the pages render is asserted against WCAG AA (BR-REQ-070-02 criterion 4). The club blue is 8.22:1 on the page background; `blueInk` is a hover and pressed step, not a contrast remedy. One documented failure is asserted as a failure: the secondary is 2.64:1 as text, so it is a surface with dark text on it and never text itself. The full audit remains an e2e concern that is not built.
- Two open branding questions are recorded rather than silently decided. The logo file states pure `#0000ff`, while the kit photograph samples at `#0d1c3d`–`#1b2843` navy — lighting does not explain that, since pure blue has no red or green channel. The vector file wins for now, being the only source that states a value rather than photographing one. The kit's navy-to-cyan gradient is captured as a token derived from that photograph, with its measured ramp written down beside it; the authoritative values are in the printer's file.
- Email action tokens (BR-REQ-036-02): `email_action_tokens`, a 32-byte base64url secret that exists only in the email that carried it, and a SHA-256 hash that is the only thing stored. Purpose-scoped, expiring, single use. Three entry points — issue, read, consume — and which one a route uses is a security decision: the read path runs inside `SET TRANSACTION READ ONLY`, so PostgreSQL itself refuses the write that a Gmail or Outlook link prefetch would otherwise perform, and consume is one conditional `UPDATE` so two requests cannot both spend a token. Reissuing invalidates the previous active token, and two partial unique indexes make that structural rather than a habit of the issue function. A `CHECK` refuses any `token_hash` that is not 64 lowercase hex characters, so a raw secret cannot be stored even by a direct insert that bypasses the module.
- The transactional outbox (BR-REQ-080-02): `email_outbox`, with `enqueueEmail` typed to take a transaction — passing the connection pool does not compile — so the row commits with the change that caused it and no provider is reachable inside it. A worker claims batches with `FOR UPDATE SKIP LOCKED` in its own transaction, sends with none open, and retries with bounded exponential backoff to a six-attempt ceiling; a permanent failure is never retried, and `last_error` is redacted of anything token-shaped. Criterion 3, concurrent workers, is unproven rather than tested: PGlite is single-connection and a green test against it would prove only that the SQL parses.
- The email adapter boundary and delivery modes (BR-REQ-080-03): a two-method interface, a capture adapter that is the mailbox in local and test, and a Mailgun stub with no network call and no SDK behind it — it throws, naming the missing sending domain and templates, rather than swallowing mail while looking healthy. Startup now refuses live delivery outside production, any non-capture mode in local or test, allowlist mode with an empty or malformed list, and a transmitting mode without credentials. QA subjects are prefixed `[QA]`, and allowlist membership is compared by canonical email identity rather than by string, so a Gmail alias of an authorized address is authorized too.
- 128 new unit and integration tests, 243 in total, and 18 end-to-end. Nothing routes to any of the above yet: the registration form, the token pages and the job endpoint all wait on the domain and the club's approved texts.
- Public event pages: `/ro/evenimente` and `/ro/evenimente/[slug]`, with localized pathnames per `AGENTS.md` §9.2 — the same pages are `/en/events` and `/en/events/[slug]`. Server Components, mobile-first, every fact rendered as text (BR-REQ-010-01, BR-REQ-011-01, BR-REQ-020-01, BR-REQ-040-01, BR-REQ-040-02, BR-REQ-070-03).
- `SportsEvent` and `SportsOrganization` JSON-LD, with the event's own UTC offset on start and end times and an organizer reference to the club `@id` (BR-REQ-052-02). Logo and `sameAs` are absent until the club supplies them; the requirement is not yet fully met.
